4. ЗАФИКСИРУЙ ТЕКУЩУЮ АРХИТЕКТУРУ
==================================================

Особенно документируй:

YouTube channel selection
Video catalog
Catalog sync
Catalog status
Pagination
Resume/continue
Reconcile
Ownership/security
Frontend Studio
Cabinet
Onboarding

Обязательно зафиксируй архитектурные решения Stage 3:

- Video остаётся единственной catalog table.
- unique (channel_id, youtube_video_id).
- YouTube является source of truth.
- MoyaStudia хранит metadata/cache.
- youtube_* snapshot fields отделены от будущих working fields.
- list_videos работает для выбранного channel.
- uploads playlist используется для catalog sync.
- initial sync page-based/resumable.
- максимум 50 видео на YouTube page.
- sync не требует Celery/Redis/background worker.
- Studio не делает полный live fetch при каждом открытии.
- local cache является основным источником после initial import.
- reconcile удаляет отсутствующие локальные videos только после полного успешного прохода.
- partial/failed reconcile не уничтожает существующий cache.
- unavailable video не должен автоматически считаться deleted.
- API /channels/{id}/videos отдаёт только локальный cache.
- YouTube page tokens не должны попадать во frontend.
- /catalog/sync/continue продолжает одну страницу.
- initial import может быть PARTIAL до COMPLETE.
- LOADING recovery теперь использует существующий /continue.
- server-side lease/concurrency protection остаётся источником истины.

Не меняй эти архитектурные решения.

9. PACKAGE-LOCK
==================================================

Есть известное незакоммиченное изменение:

apps/web/package-lock.json

В нём появилась строка:

"peer": true

Происхождение по Git history определить не удалось.

НЕ угадывай её происхождение.

Проверь:
- действительно ли это единственное изменение;
- связано ли оно с package.json;
- есть ли способ безопасно определить, является ли это результатом npm install/npm version.

После анализа:

если изменение не требуется проекту и его происхождение неизвестно —
НЕ включай его автоматически в документационный commit.

Если считаешь, что его нужно сохранить, сначала объясни почему и НЕ коммить без отдельного подтверждения.
